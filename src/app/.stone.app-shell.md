# App Shell

## Purpose and Design Decisions

`src/app/` e seus componentes compartilhados estruturam as rotas do Next.js App Router, tipografia global e tokens semânticos de tema:

- **Landing Page estática com ilhas interativas (`/` em `src/app/page.tsx`)**: Server Component com link de pular conteúdo (`skip-link`), `<SiteHeader />` (barra responsiva de árvore única com transição inline-para-popover nativo e auto-ocultação por scroll), seção hero assimétrica, `<LandingSpecimen />` (provador interativo ao vivo dos estilos e acabamentos), catálogo dos 11 conjuntos em `#styles`, fluxo de 3 passos em `#workflow`, acordeão nativo `<details>` não-exclusivo em `#faq` e múltiplos CTAs diretos para `/playground` sem login ou barreira de entrada.
- **Rota dedicada do Playground (`/playground` em `src/app/playground/page.tsx`)**: Server Component com `metadata.title: 'Playground | Smolji'` que renderiza `<PlaygroundClient />` (`src/components/PlaygroundClient.tsx`). `<PlaygroundClient />` carrega `../App` via `next/dynamic(..., { ssr: false })` com tela de carregamento `<progress>` na mesma identidade Paper/Graphite.
- **Tipografia, anti-FOUC e tokens CSS (`src/app/layout.tsx` e `src/app/globals.css`)**: Auto-hospeda `Bricolage_Grotesque`, `Plus_Jakarta_Sans` e `JetBrains_Mono` via `next/font/google`, declara `<meta name="color-scheme" content="light dark" />` e injeta `THEME_INIT_SCRIPT` antes da hidratação para respeitar `prefers-color-scheme` e overrides explícitos (`smolji_theme`). `globals.css` define a paleta **Printmaker's Stamp Foundry** (Paper `#F6F2EA`/`#FDFBF7` no claro, Graphite `#161513`/`#1F1D1A` no escuro e Vermilion `#C23E1A`/`#F06A43`), suporte a `light-dark()`, transições `@starting-style` para `<dialog>`/`popover`, `<details>::details-content` e `@media (forced-colors: active)`.

## Invariants

- `/playground` permanece 100% acessível diretamente via `<Link href="/playground">`, sem autenticação, cadastro ou redirecionamento obrigatório.
- `src/components/PlaygroundClient.tsx` mantém `"use client"` no topo e importa `../App` exclusivamente via `dynamic(() => import('../App'), { ssr: false })`.
- `src/app/layout.tsx` e `src/app/page.tsx` permanecem Server Components sem acesso direto a APIs exclusivas do navegador.
- Nenhum cabeçalho (`h1`–`h6`) é colocado dentro de `<summary>` no acordeão FAQ de `/`.

## Integration Contracts

- **Rota raiz (`/`)**: Renderizada por `src/app/page.tsx`, consumindo `EMOJI_STYLES` e `getEmojiUrl` de `emoji-utils`, mais os componentes `SiteHeader`, `LandingSpecimen` e `SmoljiMark`.
- **Rota `/playground`**: Renderizada por `src/app/playground/page.tsx` -> `src/components/PlaygroundClient.tsx` -> `src/App.tsx` (`studio`).
- **Componentes de shell compartilhados**:
  - `src/components/SiteHeader.tsx`: navegação responsiva com `ResizeObserver`, Popover API e fallback de scroll.
  - `src/components/SiteThemeToggle.tsx`: alternador claro/escuro guiado por CSS sincronizado com `<meta name="color-scheme">`.
  - `src/components/SmoljiMark.tsx`: emblema SVG autoral dobrado da marca.

## Anti-Patterns

- Importar `src/App.tsx` sem `ssr: false` em `src/app/playground/page.tsx` ou converter `src/app/page.tsx` em Client Component inteiro: prejudica prerender/LCP e quebra isolamento SSR.
- Exigir login ou adicionar banners comerciais/placeholders na rota `/playground` ou antes dela: viola o fluxo direto ao editor.
- Duplicar árvores DOM distintas para menu desktop e mobile no header (`navbar` único via `.is-wide` evita dessincronização de foco e estado).
